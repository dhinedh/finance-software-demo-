# Retail Sales, Collection & Outstanding Management System

A high-performance, offline-capable, browser-based ERP and financial verification dashboard designed for distribution businesses managing ~300 retailers across 5 geographical beats.

---

## 1. Business Purpose & Architecture

This application operates **entirely client-side in the browser** using **IndexedDB via Dexie.js**. It is designed specifically for a business owner who manually logs daily sales and collections to independently verify and audit billing records generated by third-party billing software.

### Core Workflow:
```
Retailer Management ➔ Daily Sales Entry ➔ Collection Entry ➔ Bill-wise Allocation ➔ Outstanding Engine ➔ Retailer Ledger ➔ Beat-wise Reports ➔ Day-End Verification
```

---

## 2. Key Modules Implemented

1. **Dashboard (`DashboardPage`)**: Real-time financial summary cards (Today's Sales, Cash, GPay, Cheques, Total Outstanding, Active Beats), Recharts sales vs collection trend, beat-wise outstanding breakdown, top 10 debtors, recent transaction feeds, and day-end mismatch alerts.
2. **Beat Management (`BeatsPage`)**: Geographical route configuration (Bazaar Beat, Gandhi Road Beat, Keelapalam, Bus Stand, Other Beat). Prevents deletion of beats with existing transaction history.
3. **Retailer Master (`RetailersPage`, `RetailerDetailModal`)**: Complete directory of ~300 retailers with opening balance, opening balance date, assigned beat, phone, address, and fast 2-3 letter autocomplete with keyboard navigation.
4. **Daily Sales Entry (`SalesPage`, `SaleFormModal`)**: Rapid entry with auto serials (`S-YYYYMMDD-001`), auto-populated beat, duplicate bill warnings, GST breakdown, and transaction editing with audit reasons.
5. **Collection Entry (`CollectionsPage`, `CollectionFormModal`)**: Bill-level payment allocation across single or multiple bills (not assuming oldest bill is paid), supporting Cash, GPay, Bank Transfer, and Cheques (Received, Cleared, Bounced).
6. **Outstanding Management (`OutstandingPage`)**: Formula: `Closing Outstanding = Opening Outstanding + Sales - Confirmed Collections`. Includes 0–60+ days ageing analysis and beat-level aggregation.
7. **Day-End Verification (`DayEndPage`)**: Date-by-date reconciliation ensuring previous day closing strictly equals next day opening. Flags unverified variances without silently adjusting figures.
8. **Retailer Ledger (`LedgerPage`)**: Chronological transaction statements with opening balance, bill debits, payment credits, allocation details, and running balances with one-click print, PDF and Excel export.
9. **Financial Reports (`ReportsPage`)**: Daily Sales, Daily Collections, Beat-wise Sales, Beat-wise Outstanding, Ageing Analysis with Date/Beat/Retailer filters, pagination, PDF and Excel (xlsx) export.
11. **Collection Schedule (`CollectionSchedulePage`)**: Dedicated tracking for payment recoveries due Today, Tomorrow, Next 7 Days, and Overdue Pending bills with 1-click collection receipts and printable salesmen target sheets.
12. **Daily Expenses (`ExpensePage`)**: Operational overheads, fuel/transport, salesman DA, vehicle repairs, and refreshments with sequential vouchers (`EXP-YYYYMMDD-001`), payment mode classification, and cash drawer outflow auditing.
13. **Audit Trail (`AuditPage`)**: Local audit registry recording timestamp, entity type, action (CREATE, UPDATE, VOID, RESTORE, CORRECTION), previous state vs new state, reason, and operator name.
14. **Backup & Disaster Recovery (`BackupPage`)**: Complete JSON database export/import with schema validation, relational integrity preservation, emergency pre-restore snapshot, and multi-sheet Excel summary export.
15. **Settings (`SettingsPage`)**: Agency metadata, operator identity, financial year start, and clean production start reset utilities.

## 3. Financial Invariants & Rules

- **Paise Precision**: All money is stored internally as integer paise (`1 Rupee = 100 paise`) to prevent floating-point inaccuracies.
- **Cheque Clearance**: Uncleared (`RECEIVED`) cheques are tracked separately and do not reduce confirmed outstanding until marked `CLEARED`. Bounced cheques immediately restore the outstanding balance.
- **Soft Deletion / Voiding**: Transactions cannot be permanently deleted; they are voided with mandatory reason logging for audit compliance.
- **Non-destructive History**: Reassigning a retailer's beat preserves the historical beat applicable at the time each invoice was created.

## 4. Automated Financial Test Suite

The system includes 17 automated unit and integration tests covering every mandatory scenario:

1. Sales increase outstanding correctly.
2. Partial collection reduces outstanding correctly.
3. Full collection settles a bill.
4. Multiple collections against one bill work correctly.
5. One collection allocated to multiple bills works correctly.
6. Cash collection totals exclude GPay and cheque.
7. GPay collection is included in confirmed collections.
8. Uncleared cheque does not reduce confirmed outstanding.
9. Bounced cheque restores outstanding.
10. Previous closing becomes next opening.
11. Historical transaction correction recalculates affected balances.
12. Duplicate bill detection works.
13. Retailer ledger calculates correctly.
14. Beat-wise outstanding matches retailer-wise totals.
15. Backup and restore preserve all records.
16. Date filtering produces correct reports.
17. Audit records preserve modifications.

Run tests anytime with:
```bash
npm test
```

## 5. Technology Stack

- **Frontend**: React 18, TypeScript, Tailwind CSS
- **Build Tool & PWA**: Vite 6, `vite-plugin-pwa` (Service Worker caching for full offline capability)
- **Database**: IndexedDB via Dexie.js & `dexie-react-hooks`
- **Charts**: Recharts
- **Icons**: Lucide React
- **Date Handling**: `date-fns`
- **Exports**: `jspdf`, `jspdf-autotable`, `xlsx` (SheetJS)
- **Testing**: Vitest with `fake-indexeddb`
